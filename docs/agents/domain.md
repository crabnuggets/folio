# Domain docs

This repo uses a single-context layout:
- `GLOSSARY.md` at the repo root.
- Architecture decision records in `docs/adr/`.

## Before exploring

Read the glossary and ADRs relevant to the area being explored.
If these files are absent, proceed silently. The domain-modeling
skill creates them as terms and decisions are resolved.

## Vocabulary

Use glossary terms when naming domain concepts in issues, proposals,
hypotheses, and tests. If a needed term is missing, reconsider the
wording or note the gap for domain-modeling.

## Decisions

When a proposal contradicts an existing ADR, identify the ADR and
explain why the decision should be reconsidered.
